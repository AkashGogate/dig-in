# Frontend lane

- `index.html`, `app.js`, `mvp.css` are the MVP service screens (Server and Kitchen) plus secondary Menu setup, using `/api/v2`. `menu-setup.js` owns upload/preview/review UI and consumes the existing prepare/activate contracts through the shared request/dispatch callbacks. Read the root product/status/API docs and `backend/app/mvp/contracts.py` before changing payloads.
- `coordination-v1.html` / `coordination-v1.js` preserve the broader first scaffold against `/api/v1`; `legacy.html` preserves the earlier voice lab. Their states/contracts are separate. The newly authorized bounded service coordination lives in `service-coordination.js`: a Kitchen lineup projects canonical dish units, structured updates target each ticket’s server, and summaries are explicitly requested/displayed/printed/spoken. Do not import the legacy general task/helper/priority system, positioning, courses or shift navigation.
- Keep manual entry and tap alternatives usable. Only human Confirm and send submits the current reviewed revision. Unknown terms/table mismatches stay visibly blocked until explicit review.
- Hold/release uses the labeled text simulator unless `/api/v2/voice/status` reports `deepgram_stream`; then it streams the mic (mono PCM16 at16kHz through AudioContext) via a single-use ticket and submits the text through the normal draft/kitchen commands. Live voice is verified on synthetic clips only; do not claim noisy-room accuracy, camera inference or live Databricks. Do not persist raw transcripts/audio or restaurant state in browser storage.
- Shared state, assignment versions, stable observations, deduplication and analytics semantics belong to the backend contracts. Retry the exact uncertain envelope, including ID/time; never fabricate success on outage.
- Maintain semantic labels, visible keyboard focus, 16px input text, phone reflow and honest empty/error/unknown states. Syntax-check all changed scripts (Node VM or `node --check`), inspect labels/IDs, and exercise the actual backend/browser path before claiming runtime verification.

- `menu-document.js` owns editable OCR proposals; `menu-setup.js` prepares only corrected structured records. Extraction never activates a menu. Read docs/MENU_EXTRACTION and AGENT_TASK_MAP before changing these seams.

- `service-coordination.js` consumes shared request/dispatch/context and the backend service summary/update contracts. Summary speech is explicit, never automatic; cancel on session/view/service-state changes. Browser/device output does not guarantee headphones. Message acknowledgment/resolution never changes food milestones.

- Integrated live capture declares raw mono PCM16/16kHz using AudioContext and a local resampler (`voice-audio.js`). Capture pins session/actor/draft/revision/view; stale or abandoned async startup cannot apply to a different draft. HTTP ticket uses X-Demo-Session and optional order_id/menu_revision; direct WS uses one-time ticket plus session_id. window.DIG_IN_VOICE_WS is the full runtime endpoint. Current backend configuration is not proof that browser hardware/provider is available.
